What runs on every worker node

kubelet

Agent that takes orders from the API server and starts or stops pods on this node.

Container runtime

containerd. Pulls the image from ECR and runs the container.

kube-proxy

Sets up network rules so a Service name reaches the right pods.

VPC CNI

Gives each pod a real IP address from our VPC, so the ALB can reach the pod directly.

How it all works together

  1. 1
    We apply a deployment

    kubectl or Helm tells the API server “run 3 pods of this image”.

  2. 2
    Saved in etcd

    This becomes the cluster's desired state.

  3. 3
    Scheduler picks nodes

    Finds nodes with free CPU and memory, ideally spread across AZs.

  4. 4
    kubelet starts the pods

    Pulls the image from ECR. VPC CNI gives each pod an IP.

  5. 5
    ALB sends traffic

    Only to pods that pass their health check.

  6. 6
    Controllers keep it that way

    A pod or node dies → a replacement is created automatically.

The Ingress creates the ALB and its rules. The Service groups the app's pods, and traffic only goes to healthy pods. If one pod is down, users go to another.

Example

How LBI is deployed to EKS

  1. 1
    Push code

    Each branch goes to an environment, e.g. develop → dev.

  2. 2
    Build image

    The pipeline builds a Docker image and stores it in ECR.

  3. 3
    Helm deploy

    The pipeline updates LBI in its namespace (dev, uat, preprod or prod).

  4. 4
    New pods start

    EKS starts new LBI pods. Old pods are removed only after the new ones are healthy.

  5. 5
    Users get the new version

    CloudFront → ALB → new LBI pods. No downtime.
